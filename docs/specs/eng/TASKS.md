# TASKS.md

The build backlog. Each task is a slice that can be verified on its own. Implementation status lives on the kanban board, not here.

References: FR-xx ([PRD.md §6](PRD.md)), F-xx ([FEATURES.md](FEATURES.md)), DEC-xxx ([DECISIONS.md](DECISIONS.md)).

## 0. Choose the access stage first

Before TASK-03, record the project's access stage as a decision ([auth/access/README.md §3](auth/access/README.md)). **Stage 1, static-roles, is the default**, and the tasks below are written for it. For stage 2 (single-org), swap tasks as listed in [auth/access/migration.md §2](auth/access/migration.md). A project that must be multi-tenant from the start also adds [saas/migration.md §2](saas/migration.md).

## 2. Tasks

### TASK-01: Bootstrap the Bun monorepo
- **Goal:** Workspaces `apps/{api,web}`, `packages/{shared,auth,db,ui}`; `bun run dev` starts API and web.
- **Refs:** FR-01, [ARCHITECTURE.md §2](ARCHITECTURE.md).
- **Acceptance:** `bun install` succeeds; both processes run; shared base `tsconfig`; lockfile committed; versions pinned; the web dev server proxies `/api` to the API (DEC-020).

### TASK-02: Dev infrastructure
- **Goal:** `docker compose up` gives PostgreSQL 17, Redis 7 and MongoDB 8 with health checks; MongoDB init creates the writer, admin and read-only log users ([log-storage.md §2](observability/log-storage.md)); `docker-compose.test.yml` for tests; `.env.example` lists every variable in [ARCHITECTURE.md §7](ARCHITECTURE.md).
- **Depends on:** TASK-01.
- **Acceptance:** containers healthy; `.env.example` has no real secrets.

### TASK-03: Drizzle schema and migrations
- **Goal:** Better Auth schema generated by the CLI + `post` table per [DATABASE.md](DATABASE.md); Drizzle Kit migrations; dev seed.
- **Depends on:** TASK-02. (Generation needs a minimal `auth.ts`; regenerate in TASK-04 if anything changes.)
- **Acceptance:** no `role` table; migrations idempotent; seed creates one `super_admin` and example posts, is idempotent, refuses production; indexes per [DATABASE.md §4](DATABASE.md).

### TASK-12: Logger, telemetry, module tag, redaction, error handler
- **Goal:** `utils/logger` (with `moduleScope`), `utils/telemetry` (scrubber, `log` and `memory` sinks, retention table), `utils/error` (`moduleError`, global handler), root app with prefix `/api`, `health` module.
- **Refs:** FR-13, DEC-013 to DEC-017, DEC-027, DEC-037, [observability/README.md](observability/README.md), [redaction.md](observability/redaction.md).
- **Depends on:** TASK-01.
- **Acceptance:** items in [observability/README.md §10](observability/README.md) except the MongoDB ones; [redaction.md §7](observability/redaction.md) (vendor item excluded); health per [API.md §3.2](API.md).

### TASK-15: MongoDB log sink and manual retention
- **Goal:** `utils/mongo`, `sinks/mongo.ts`, `scripts/logs-setup.ts` (indexes), `scripts/logs-prune.ts` (`--dry-run`, `--kind`, `--older-than`, `--user`).
- **Refs:** DEC-034, [log-storage.md](observability/log-storage.md), [DATABASE.md §8](DATABASE.md).
- **Depends on:** TASK-02, TASK-12.
- **Acceptance:** [log-storage.md §8](observability/log-storage.md).

### TASK-07: Redis cache helper
- **Goal:** `utils/redis` + `utils/cache` (`get/set/del/wrap/delPattern`), per-module TTL, memory fallback when `REDIS_URL` is empty; startup refuses production without `REDIS_URL`.
- **Depends on:** TASK-02, TASK-12.
- **Acceptance:** tests for hit, miss, TTL; `delPattern` uses `SCAN`; without Redis the tests pass and `cache.fallback` is emitted once; `NODE_ENV=production` without `REDIS_URL` fails startup.

### TASK-13: Graceful shutdown
- **Goal:** On SIGTERM/SIGINT: stop accepting requests, `telemetry.flush()` (MongoDB buffer), close PostgreSQL, Redis and MongoDB clients, exit 0.
- **Depends on:** TASK-12, TASK-15.
- **Acceptance:** `app.stopping` logged and stored; buffered events written; exit in < 10 s; no hanging connections.

### TASK-18: Test harness
- **Goal:** `apps/api/tests/{helpers,modules,utils,e2e}` and `apps/web/tests/{helpers,features,lib,components}` per [TESTING.md](TESTING.md); `test` and `test:e2e` scripts; test PostgreSQL and `docker-compose.test.yml` wiring; CI check that every module and feature has its test folder.
- **Depends on:** TASK-01, TASK-12.
- **Acceptance:** [TESTING.md §7](TESTING.md) items 3 and 4; an example test in each level passes.

### TASK-04: Better Auth server and access control
- **Goal:** `createAuth` in `packages/auth` per [auth/README.md §2](auth/README.md); `utils/auth/{roles,access,auth,hooks,audit}.ts` per [auth/access/static-roles.md](auth/access/static-roles.md); mount at `/api/auth/*` with `module: "auth"`; Redis secondary storage; admin plugin with `ac` and `roles` (DEC-033 grants); no `adminUserIds`.
- **Depends on:** TASK-03, TASK-07, TASK-12.
- **Acceptance:** sign-up, sign-in, sign-out and Google work; Google with an existing verified email links; sixth sign-in in 60 s → 429; audit events from [auth/README.md §6](auth/README.md); guard rules from [static-roles.md §7](auth/access/static-roles.md), including impersonation endpoints → 404 for `super_admin`; the merged statement has no impersonate actions; no `/api/api/auth` path; duplicate resource keys fail startup; real error codes recorded in [auth/README.md §5](auth/README.md) and real paths in [API.md §3.1](API.md).

### TASK-05: Auth and permission macros, `me` module
- **Goal:** `auth` and `permission` macros (DEC-010, default deny); `GET /api/me/permissions`.
- **Depends on:** TASK-04.
- **Acceptance:** 401 without session; 403 without permission; `user`/`session` typed in handlers; only `Permission` values compile; matrix test and compiled-roles snapshot per [static-roles.md §11](auth/access/static-roles.md); tests in `tests/modules/me/`.

### TASK-06: Admin module (F-03)
- **Goal:** `modules/admin` with `permissions.ts` (explicit built-in actions + `role:read`) and `GET /api/admin/roles`.
- **Depends on:** TASK-05.
- **Acceptance:** [API.md §3.5](API.md) and F-03; `user` → 403; every registry role listed with compiled permissions; tests in `tests/modules/admin/` and `tests/e2e/admin/`.

### TASK-08: Posts module (F-04)
- **Goal:** Endpoints in [API.md §3.4](API.md) with the DEC-008 layout, `moduleScope('posts')`, `moduleError` codes.
- **Depends on:** TASK-05, TASK-07.
- **Acceptance:** F-04; required tests per [TESTING.md §3.1](TESTING.md) in `tests/modules/posts/` and flows in `tests/e2e/posts/`; cache hit p95 < 50 ms measured from `http.request`.

### TASK-14: Web skeleton
- **Goal:** Structure per [apps/web/README.md](../../../apps/web/README.md): `routes/`, `features/`, `lib/api.ts`, `lib/auth-client.ts`, QueryClient, feature-boundary lint rule, Tailwind v4 + `packages/ui` tokens.
- **Depends on:** TASK-01 (Eden needs `type App` from TASK-12).
- **Acceptance:** cross-feature deep import fails lint; Eden calls `/api/health` from the browser and during SSR; web dev port recorded in [TESTING.md §5](TESTING.md).

### TASK-09: Web auth (F-05)
- **Goal:** `auth` feature: login, register, Google, logout, `beforeLoad` redirects, `usePermissions()` / `can()`.
- **Depends on:** TASK-05, TASK-14, TASK-18.
- **Acceptance:** F-05; tests in `tests/features/auth/`; flows in `e2e/auth/`.

### TASK-10: Forms and profile
- **Goal:** TanStack Form for auth forms; `profile` feature with `updateUser`.
- **Depends on:** TASK-09.
- **Acceptance:** client validation matches the API; server errors per field; tests in `tests/features/profile/`; flows in `e2e/profile/`.

### TASK-16: Web posts feature
- **Goal:** `posts` feature: list, detail, create, edit, delete, gated by `can()`.
- **Depends on:** TASK-08, TASK-09.
- **Acceptance:** loading, empty, error and forbidden states; edit/delete only on own posts unless `posts:manage_all`; mutations invalidate the list; tests in `tests/features/posts/`; flows in `e2e/posts/`.

### TASK-17: Web admin feature
- **Goal:** `admin` feature: users list and detail, change role, ban/unban, sessions list and revoke, role catalogue.
- **Depends on:** TASK-06, TASK-09.
- **Acceptance:** every page and action gated per [static-roles.md §6](auth/access/static-roles.md); destructive actions confirm and name the target user ID; own role cannot be changed; tests in `tests/features/admin/`; flows in `e2e/admin/`.

### TASK-19: E2E suites
- **Goal:** All required API E2E flows ([TESTING.md §3.2](TESTING.md)) and web E2E flows ([TESTING.md §5](TESTING.md)) complete and in CI.
- **Depends on:** TASK-08, TASK-10, TASK-16, TASK-17.
- **Acceptance:** every listed flow exists in its module/feature folder and passes; web flows validated by the E2E runner; `smoke` tags set.

### TASK-11: Operations and DX
- **Goal:** CI (install, typecheck, lint, test, migrate, E2E), setup docs, prune runbook, bootstrap-time baseline.
- **Depends on:** all tasks above.
- **Acceptance:** CI green; bootstrap time recorded in [PRD.md §9](PRD.md); the prune runbook ([log-storage.md §5.4](observability/log-storage.md)) is in the setup docs.
